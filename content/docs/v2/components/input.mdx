```tsx
import { Input } from '@letterstack/react';

<Input name="email" type="email">
  <Input.Label>Email</Input.Label>
  <Input.Field placeholder="you@example.com" />
  <Input.Description>We send one issue every other Thursday.</Input.Description>
  <Input.Error />
</Input>
```

The wrapper generates the ids and wires `aria-describedby` and `aria-invalid` across the
slots. That plumbing is the reason to use it over a bare `<input>`.

## Validation

`Input` does not validate. It renders the state you give it, so whatever owns your form
schema stays in charge.

```tsx tab="Server action" lineNumbers
import { Input } from '@letterstack/react';

export function SubscribeFields({ errors }: { errors?: { email?: string } }) {
  return (
    <Input name="email" type="email" required invalid={Boolean(errors?.email)}>
      <Input.Label>Email</Input.Label>
      <Input.Field />
      <Input.Error>{errors?.email}</Input.Error>
    </Input>
  );
}
```

```tsx tab="React Hook Form" lineNumbers
const { register, formState } = useForm<Values>();

<Input name="email" type="email" invalid={Boolean(formState.errors.email)}>
  <Input.Label>Email</Input.Label>
  <Input.Field {...register('email')} />
  <Input.Error>{formState.errors.email?.message}</Input.Error>
</Input>;
```

<Callout type="warn" title="Placeholders are not labels">
  A placeholder disappears the moment someone types, and screen readers treat it
  inconsistently. Always render `Input.Label`; hide it visually if the design demands it.
</Callout>

## Announcing errors

`Input.Error` is `aria-live="polite"`. Errors are announced when they appear rather than
interrupting whatever is being read.

```txt title="Announcement order"
1. "Email, edit text, required"
2. (user submits)
3. "Enter an email address"
```

## Data attributes

| Attribute | Values |
| --- | --- |
| `data-ls-input` | present on the root |
| `data-invalid` | present when `invalid` |
| `data-required` | present on the label when `required` |
| `data-filled` | present once the field has a value |
